# seed19で残る1サンプルの差

追加の分割6も全32WAVが原版・独立採取と全体一致した（茜981.048秒・葵921.225秒、4337793 PCMサンプル）。[全入力の検証](evidence/seed19-shard6-wav.json)。これで終了済み分割0〜6は修正前223/224一致。分割7と、べき乗修正後のcase117は別の実行として比較中であり、下の初回失敗記録はそのまま保持する。

2026-10-13。最大24生成単位・128文章×両音声の通常原版WAV比較は継続中。分割0〜4の160WAVは全体一致。分割5も全32入力を終えたが、茜16件・葵15件が全体一致し、葵case117だけ不一致だった。現時点の終了済み範囲は191/192一致であり、全256件の結果ではない。

入力は `火閉漢字私六零四木1月78金土Ｂ六火A火三。`。葵のWAVは両方675304バイトで、PCM16の1サンプルが1だけ違う。最初の異なるバイトは274590。原版WAVのSHA256は `28769406e32b762f656dc0e32999637fe061ae7e9cf7cb3e63eca6a9c8819fe5`、Goは `32f91ee20fde63c3f20cf71f0e3c21ec428ce954e69d8f6d647983b7f0245d01`。原版は先の独立した通常SDK採取とも同一ハッシュであり、採取による原版変化として除外しない。

[終了した分割の全32入力](evidence/seed19-shard5-wav.json)には失敗も含め、実ファイルから再計算したハッシュと異なるPCM位置を保存した。CPUはAMD Family 25 Model 33、6スレッド、AVX512畳み込みなし、Go 1.26.8・CGO=0。

`AOIKANE_SEED19_CASE117_REFERENCE_AUDIT=1` で `TestSeed19Case117ReferenceWAV` を実行すると、DLLなしで両音声の原版全体ハッシュと厳密比較する。失敗した葵も必ず含む。通常の軽量テストではスキップされるため、その成功を音声一致の証拠にはしない。演算の丸め差が候補だが、原因はまだ特定していない。

同じ葵入力を通常比較で再実行し、315.854秒で同じWAVハッシュ・位置の不一致を再現した。原版モデルの読取り観測と第7回圧縮処理の演算観測も、採取したWAV全体が通常原版と一致しており、この調査範囲では観測による音声変化はない。

実際の原版入力でGoの圧縮処理を14回再計算すると、334800個のfloat32値のうち第7回の240値だけ不一致だった。さらに原版の `pow_scalar` の110指数をGoの `math.Pow(10,指数)` へ与えると、index23だけ最下位ビットが違った。指数は `bf947b96`、原版出力は `3d8dae11`、Go出力は `3d8dae12`。同じ回の平方根110値は全ビット一致した。[全110値と検証ハッシュ](evidence/seed19-compressor-pow-original.json)。原版のべき乗の丸めを再構築し、最終WAVまで差が解消することを検証する作業が残る。音声の1サンプル差を許容する変更はしていない。
